llama.cpp v1.1.0 and Server Security Hardening Report

🚀 v1.1.0 Feature Highlights

The v1.1.0 release brought several significant additions and optimizations to the inference capabilities:

  • New Model Families: Introduction of Inkling 2 (base, Mini, and DSpark), Domyn Edge 4B, Zaya1 8B, RAON-1-mini, and Hy4 flash.
  • Performance Improvements: Splitting DFlash speculative decoding into separate draft methods.
  • API Modernization: Deprecation of the old llama_batch API in favor of llama_batch_ext.

🛡️ llama-server Security Hardening (v1.0.0+)

The hardening efforts in llama-server are focused on making the local LLM runtime robust against external and internal threats. Key improvements include:

  • Mitigating SSRF: Critical updates restricted the forwarding of authentication headers through the CORS proxy, eliminating a major path for Server-Side Request Forgery (SSRF) attacks.
  • Access Control: Modern deployments often require API keys to protect the server when exposed beyond the local machine.
  • Runtime Safety: Continuous patching addresses low-level issues like uninitialized heap memory disclosure in components like ggml-rpc.

Best Practice: Operators should run inference servers in a secure, isolated environment and use strong access control mechanisms.
